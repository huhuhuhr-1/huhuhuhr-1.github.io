sealos实战

Sealos实战：从零开始部署和管理Kubernetes集群 概述 本文档详细介绍了如何使用Sealos在多台服务器上部署和管理Kubernetes集群，包括环境准备、集群部署、应用部署、配置管理、扩容、容灾、升级和回滚等完整运维流程。我们将以三台服务器为例，展示从零开始构建到运维整个Kubernetes集群的完整过程。 1. 环境准备 1.1 服务器规划 我们使用三台服务器作为示例： Master节点（控制平面）：192.168.1.100 Worker节点1：192.168.1.101 Worker节点2：192.168.1.102 1.2 前提条件 在所有服务器上准备以下环境： 操作系统：Ubuntu 20.04 LTS 或 CentOS 8.x 硬件配置： CPU：至少2核 内存：至少4GB 磁盘：至少40GB 网络配置： 服务器之间网络互通 关闭防火墙或开放必要端口 SSH访问：确保可以从任一节点SSH到其他节点 1.3 系统准备命令 在所有节点上执行以下命令： # 关闭防火墙（生产环境建议配置具体规则）sudo ufw disable # Ubuntusudo systemctl stop firewalld # CentOSsudo systemctl disable firewalld# 关闭Swapsudo swapoff -asudo sed -i '/ swap / s/^\(.*\)$/#\1/g' /etc/fstab# 允许iptables转发sudo modprobe overlaysudo modprobe br_netfiltercat &lt;&lt;EOF | sudo tee /etc/modules-load.d/k8s.confoverlaybr_netfilterEOFcat &lt;&lt;EOF | sudo tee /etc/sysctl.d/k8s.confnet.bridge.bridge-nf-call-iptables = 1net.bridge.bridge-nf-call-ip6tables = 1net.ipv4.ip_forward = 1EOFsudo sysctl --system# 安装Dockercurl -fsSL https://get.docker.com | bash -s docker --mirror Aliyunsudo systemctl enable dockersudo systemctl start docker# 设置国内镜像源（可选，提高拉取速度）sudo mkdir -p /etc/dockercat &lt;&lt;EOF | sudo tee /etc/docker/daemon.json{ "registry-mirrors": [ "https://docker.mirrors.ustc.edu.cn", "https://hub-mirror.c.163.com" ], "exec-opts": ["native.cgroupdriver=systemd"]}EOFsudo systemctl restart docker 2. 安装Sealos 在Master节点（192.168.1.100）上安装Sealos： # 安装sealoswget -c https://ghproxy.com/github.com/labring/sealos/releases/download/v4.4.0/sealos_4.4.0_linux_amd64.tar.gz \ -O - | sudo tar -zx -C /usr/local/bin# 为sealos添加执行权限sudo chmod +x /usr/local/bin/sealos# 验证安装sealos version 3. 创建Clusterfile定义集群 创建一个名为Clusterfile的文件来定义集群配置： apiVersion: apps.sealos.io/v1beta1kind: Clustermetadata: name: my-clusterspec: image: - kubernetes:v1.25.0 - calico:v3.24.1 hosts: - ips: - "192.168.1.100" # Master节点IP roles: [ "master", "control-plane" ] - ips: - "192.168.1.101" # Worker节点IP 1 - "192.168.1.102" # Worker节点IP 2 roles: [ "node" ] 这个配置文件定义了： 使用Kubernetes v1.25.0版本 使用Calico作为CNI网络插件 一台Master节点和两台Worker节点 4. 部署Kubernetes集群 在Master节点上运行以下命令部署集群： # 使用Clusterfile部署集群sealos run -f Clusterfile# 或者直接使用命令行参数部署sealos run kubernetes:v1.25.0 calico:v3.24.1 \ --masters 192.168.1.100 \ --nodes 192.168.1.101,192.168.1.102 部署完成后，Sealos会： 安装Kubernetes组件 配置etcd集群 初始化Master节点 加入Worker节点 配置网络插件Calico 验证集群状态： # 如果sealos自动配置了kubectlkubectl get nodes# 或者使用以下命令获取集群访问信息sealos kubeconfig -f Clusterfile --host 192.168.1.100 预期输出： NAME STATUS ROLES AGE VERSION192.168.1.100 Ready control-plane,master 5m v1.25.0192.168.1.101 Ready &lt;none&gt; 4m v1.25.0192.168.1.102 Ready &lt;none&gt; 4m v1.25.0 5. 理解Pod和Node的分配机制 5.1 Node（节点） Node是集群中的工作机器（物理机或虚拟机），负责运行Pod。在我们的例子中： 192.168.1.100：Master节点，具有控制平面角色 192.168.1.101和192.168.1.102：Worker节点，用于运行工作负载 5.2 Pod（容器组） Pod是Kubernetes中最小的部署单元，通常包含一个或多个紧密相关的容器。 5.3 调度机制 Kubernetes调度器（kube-scheduler）负责决定Pod在哪个Node上运行。它考虑以下因素： 资源需求：CPU、内存等 节点标签（Labels）和节点选择器（Node Selector） 污点（Taints）和容忍度（Tolerations） 亲和性（Affinity）和反亲和性（Anti-Affinity） 6. 部署应用到集群 6.1 准备Docker镜像 假设我们有一个名为my-web-app:latest的Docker镜像，包含一个简单的Web应用。 首先，确保镜像在所有节点上都可用： # 在所有节点上拉取镜像sudo docker pull my-registry/my-web-app:latest# 或者在一台机器上保存镜像为tar文件，然后分发到其他节点docker save -o my-web-app.tar my-registry/my-web-app:latestscp my-web-app.tar user@192.168.1.101:~/scp my-web-app.tar user@192.168.1.102:~/# 在其他节点上加载镜像docker load -i my-web-app.tar 6.2 创建应用部署配置 创建一个名为web-app-deployment.yaml的文件： apiVersion: apps/v1kind: Deploymentmetadata: name: my-web-app namespace: defaultspec: replicas: 2 # 初始副本数 selector: matchLabels: app: my-web-app template: metadata: labels: app: my-web-app spec: containers: - name: web-container image: my-registry/my-web-app:latest ports: - containerPort: 80 env: - name: ENV value: "production" resources: requests: memory: "64Mi" cpu: "250m" limits: memory: "128Mi" cpu: "500m"---apiVersion: v1kind: Servicemetadata: name: my-web-app-servicespec: selector: app: my-web-app ports: - protocol: TCP port: 80 targetPort: 80 type: LoadBalancer # 或者使用NodePort或ClusterIP 6.3 通过Sealos部署应用 使用Sealos可以创建应用包来部署应用，也可以使用kubectl直接应用YAML配置： 方法1：使用kubectl # 应用YAML配置kubectl apply -f web-app-deployment.yaml# 验证部署kubectl get deploymentskubectl get podskubectl get services 方法2：使用Sealos应用包 首先创建应用包（Application Package）： # 创建应用包目录结构mkdir my-web-app-pkgcd my-web-app-pkg# 创建Kubefile定义应用包cat &gt; Kubefile &lt;&lt; EOFFROM scratchCOPY web-app-deployment.yaml .CMD ["kubectl apply -f web-app-deployment.yaml"]EOF# 构建应用包镜像sealos build -t my-registry/my-web-app-pkg:latest .# 推送镜像到仓库（如果需要）sealos push my-registry/my-web-app-pkg:latest# 运行应用包sealos run my-registry/my-web-app-pkg:latest 7. 配置参数注入 7.1 通过ConfigMap注入配置 创建一个ConfigMap来存储配置参数： # 创建ConfigMapkubectl create configmap app-config \ --from-literal=database.host=192.168.1.200 \ --from-literal=database.port=3306 \ --from-literal=app.mode=production 更新Deployment以使用ConfigMap： apiVersion: apps/v1kind: Deploymentmetadata: name: my-web-appspec: replicas: 2 selector: matchLabels: app: my-web-app template: metadata: labels: app: my-web-app spec: containers: - name: web-container image: my-registry/my-web-app:latest ports: - containerPort: 80 env: - name: DATABASE_HOST valueFrom: configMapKeyRef: name: app-config key: database.host - name: DATABASE_PORT valueFrom: configMapKeyRef: name: app-config key: database.port - name: APP_MODE valueFrom: configMapKeyRef: name: app-config key: app.mode volumeMounts: - name: config-volume mountPath: /etc/config volumes: - name: config-volume configMap: name: app-config 7.2 通过Secret注入敏感配置 创建一个Secret来存储敏感信息（如密码、密钥）： # 创建Secretkubectl create secret generic app-secret \ --from-literal=db-password=supersecretpassword \ --from-literal=api-key=your-api-key 更新Deployment以使用Secret： apiVersion: apps/v1kind: Deploymentmetadata: name: my-web-appspec: replicas: 2 selector: matchLabels: app: my-web-app template: metadata: labels: app: my-web-app spec: containers: - name: web-container image: my-registry/my-web-app:latest ports: - containerPort: 80 env: - name: DATABASE_HOST valueFrom: configMapKeyRef: name: app-config key: database.host - name: DB_PASSWORD valueFrom: secretKeyRef: name: app-secret key: db-password - name: API_KEY valueFrom: secretKeyRef: name: app-secret key: api-key 8. 节点扩容 8.1 扩容Worker节点 当需要增加Worker节点来提供更多的计算资源时： 在新的服务器上准备环境（按照1.3节的系统准备命令） 使用Sealos添加节点： # 添加新的Worker节点sealos add --nodes 192.168.1.103# 验证节点是否加入集群kubectl get nodes 8.2 扩容应用Pod 增加应用的副本数： # 扩容到5个副本kubectl scale deployment my-web-app --replicas=5# 或者直接编辑Deploymentkubectl edit deployment my-web-app 9. 容灾策略 9.1 高可用Master节点 为避免Master节点单点故障，我们可以部署高可用集群： # 使用三个Master节点部署高可用集群sealos run kubernetes:v1.25.0 calico:v3.24.1 \ --masters 192.168.1.100,192.168.1.103,192.168.1.104 \ --nodes 192.168.1.101,192.168.1.102 9.2 备份和恢复 定期备份etcd数据和Kubernetes清单： # 备份etcdETCDCTL_API=3 etcdctl snapshot save /tmp/etcd-snapshot-$(date +%Y%m%d).db \ --endpoints=https://127.0.0.1:2379 \ --cacert=/etc/kubernetes/pki/etcd/ca.crt \ --cert=/etc/kubernetes/pki/etcd/server.crt \ --key=/etc/kubernetes/pki/etcd/server.key# 使用Velero备份和恢复# 安装Velerokubectl apply -f https://github.com/vmware-tanzu/velero/releases/latest/download/velero-install.yaml# 创建备份velero backup create my-backup --selector app=my-web-app 9.3 健康检查和监控 配置Liveness和Readiness探针： apiVersion: apps/v1kind: Deploymentmetadata: name: my-web-appspec: replicas: 2 selector: matchLabels: app: my-web-app template: metadata: labels: app: my-web-app spec: containers: - name: web-container image: my-registry/my-web-app:latest ports: - containerPort: 80 livenessProbe: httpGet: path: /health port: 80 initialDelaySeconds: 30 periodSeconds: 10 readinessProbe: httpGet: path: /ready port: 80 initialDelaySeconds: 5 periodSeconds: 5 10. 应用升级和回滚 10.1 应用升级 滚动更新 使用滚动更新策略进行应用升级： # 更新部署的镜像kubectl set image deployment/my-web-app web-container=my-registry/my-web-app:v2.0# 查看升级进度kubectl rollout status deployment/my-web-app# 查看升级历史kubectl rollout history deployment/my-web-app 使用Helm进行升级（可选） 如果使用Helm管理应用： # 更新Helm Charthelm upgrade my-release my-chart --set image.tag=v2.0 10.2 升级失败回滚 如果新版本出现问题，可以快速回滚： # 查看升级历史kubectl rollout history deployment/my-web-app# 回滚到上一个版本kubectl rollout undo deployment/my-web-app# 回滚到指定版本kubectl rollout undo deployment/my-web-app --to-revision=2 10.3 集群升级 升级整个Kubernetes集群： # 使用Sealos升级集群sealos run kubernetes:v1.26.0 calico:v3.25.0 \ --masters 192.168.1.100 \ --nodes 192.168.1.101,192.168.1.102 11. 实战案例总结 通过以上步骤，我们完成了一个完整的Sealos实战流程： 环境准备：在三台服务器上配置系统环境 集群部署：使用Sealos快速部署Kubernetes集群 应用部署：将Docker镜像部署到集群中 配置管理：通过ConfigMap和Secret注入配置参数 节点扩容：添加新的Worker节点和应用Pod 容灾策略：配置高可用、备份和健康检查 升级回滚：实现应用和集群的升级与回滚 这种基于Sealos的部署方式大大简化了Kubernetes集群的部署和管理复杂度，使得运维团队可以更专注于应用本身，而不是基础设施的复杂性。 12. Kubernetes核心概念和术语 在深入了解问题排查之前，让我们先梳理Kubernetes的层级结构和核心概念，从大到小排列： 12.1 集群（Cluster） 定义：由一个或多个节点组成的容器化应用平台 实际例子：我们前面创建的名为my-cluster的Kubernetes集群 映射：一个完整的Kubernetes环境，包含控制平面和工作节点 对应命令：# 查看集群信息kubectl cluster-info# 检查集群组件状态kubectl get componentstatuses# 查看集群节点kubectl get nodes# 查看集群版本信息kubectl version# 检查集群健康状况kubectl top nodes 12.2 命名空间（Namespace） 定义：集群中的虚拟子分区，用于隔离资源 实际例子：default、kube-system、kube-public等 映射：类似于操作系统的文件夹，用于组织和隔离不同环境的资源 对应命令：# 查看所有命名空间kubectl get namespaces# 创建命名空间kubectl create namespace my-namespace# 在指定命名空间中操作资源kubectl get pods -n my-namespace# 查看命名空间详细信息kubectl describe namespace my-namespace 12.3 节点（Node） 定义：集群中的工作机器，可以是物理机或虚拟机 实际例子：我们使用的三台服务器（192.168.1.100、192.168.1.101、192.168.1.102） 映射：192.168.1.100（Master节点）、192.168.1.101和192.168.1.102（Worker节点） 对应命令：# 查看所有节点kubectl get nodes# 查看节点详细信息kubectl describe node &lt;node-name&gt;# 查看节点资源使用情况kubectl top nodes# 标记节点不可调度kubectl cordon &lt;node-name&gt;# 标记节点可调度kubectl uncordon &lt;node-name&gt;# 安全驱逐节点上的Pod（用于维护）kubectl drain &lt;node-name&gt; --ignore-daemonsets# 查看节点事件kubectl get events --field-selector involvedObject.kind=Node 12.4 Pod 定义：Kubernetes中最小的部署单元，可包含一个或多个紧密相关的容器 实际例子：my-web-app-7d5b9c8f4c-xyz12 这个Pod 映射：一个逻辑主机，包含一个或多个共享存储、网络和规格定义的容器 深入理解： Pod不是Docker Compose服务组：一个Pod通常对应一个应用实例，而不是多个相关服务 紧密相关容器：Pod中的多个容器需要共享存储和网络，协同完成一个任务 例如：主应用容器 + 日志收集容器（如Filebeat） 例如：主应用容器 + 代理容器（如Envoy） 例如：主应用容器 + Sidecar容器（如Istio Proxy） 共享资源： 网络：Pod内所有容器共享IP地址和端口空间 存储：Pod内所有容器可以共享存储卷 生命周期：Pod中的容器一起启动、停止和重启 Docker Compose到Kubernetes的映射： Docker Compose中的一个服务 → Kubernetes中的一个Pod Docker Compose中的多个服务 → Kubernetes中的多个Pod + Service 对应命令：# 查看Podkubectl get pods -n &lt;namespace&gt;# 查看Pod详细信息kubectl describe pod &lt;pod-name&gt; -n &lt;namespace&gt;# 查看Pod日志kubectl logs &lt;pod-name&gt; -n &lt;namespace&gt;# 实时查看Pod日志kubectl logs -f &lt;pod-name&gt; -n &lt;namespace&gt;# 进入Pod容器kubectl exec -it &lt;pod-name&gt; -n &lt;namespace&gt; -- bash# 查看Pod YAML配置kubectl get pod &lt;pod-name&gt; -n &lt;namespace&gt; -o yaml# 删除Pod（Deployment会自动重建）kubectl delete pod &lt;pod-name&gt; -n &lt;namespace&gt;# 查看Pod资源使用情况kubectl top pods -n &lt;namespace&gt; 12.5 容器（Container） 定义：运行应用的轻量级虚拟化环境 实际例子：my-web-app Pod中的web-container 映射：Docker容器，运行具体的应用程序 对应命令：# 查看Pod中的容器kubectl get pods -n &lt;namespace&gt; -o jsonpath='{.items[*].spec.containers[*].name}'# 查看特定容器的日志kubectl logs &lt;pod-name&gt; -c &lt;container-name&gt; -n &lt;namespace&gt;# 进入特定容器kubectl exec -it &lt;pod-name&gt; -c &lt;container-name&gt; -n &lt;namespace&gt; -- bash# 查看容器镜像kubectl get pods -n &lt;namespace&gt; -o jsonpath='{.items[*].spec.containers[*].image}'# 查看容器资源限制kubectl describe pod &lt;pod-name&gt; -n &lt;namespace&gt; 12.6 服务（Service） 定义：定义一组Pod的逻辑集合和访问策略，提供稳定的网络端点 实际例子：my-web-app-service，为my-web-app的Pod提供稳定的访问地址 映射：类似负载均衡器或代理，为一组Pod提供稳定的IP和DNS名称 深入理解： 服务发现：通过标签选择器（label selector）发现后端Pod 负载均衡：在后端Pod间分发流量，但不使用传统负载均衡算法 稳定端点：即使Pod被重新调度，Service的IP和DNS名称保持不变 服务类型： ClusterIP：仅在集群内部访问 NodePort：在集群节点上开放端口 LoadBalancer：创建外部负载均衡器 ExternalName：将服务映射到外部DNS名称 与Docker Compose的映射： Docker Compose服务间的连接 → Kubernetes中使用Service Docker Compose的links功能 → Kubernetes中使用Service DNS名称 对应命令：# 查看服务kubectl get services -n &lt;namespace&gt;# 查看服务详细信息kubectl describe service &lt;service-name&gt; -n &lt;namespace&gt;# 查看服务端点（后端Pod IP）kubectl get endpoints &lt;service-name&gt; -n &lt;namespace&gt;# 查看服务YAML配置kubectl get service &lt;service-name&gt; -n &lt;namespace&gt; -o yaml# 测试服务连通性kubectl run test-pod --image=busybox --rm -it --restart=Never -- nslookup &lt;service-name&gt;.&lt;namespace&gt;.svc.cluster.local# 端口转发到服务kubectl port-forward service/&lt;service-name&gt; 8080:80 -n &lt;namespace&gt; 12.7 控制器（Controller） 定义：确保Pod按照预期状态运行的资源对象 实际例子：Deployment、StatefulSet、DaemonSet等 映射：Deployment控制器确保my-web-app始终有2个副本运行 深入理解： 控制器类型： Deployment：管理无状态应用，支持滚动更新和回滚 StatefulSet：管理有状态应用，提供稳定的网络标识和持久存储 DaemonSet：确保所有节点运行一个Pod副本 Job/CronJob：管理一次性任务和定时任务 Pod调度与容灾： 通过污点（Taints）和容忍度（Tolerations）控制Pod调度到特定节点 通过节点亲和性（Node Affinity）和反亲和性（Node Anti-Affinity）控制Pod部署位置 通过Pod反亲和性避免相同应用的Pod运行在同一节点上，实现容灾 与Docker Compose的映射： Docker Compose的replicas → Kubernetes中的Deployment replicas Docker Compose的restart policy → Kubernetes的Pod重启策略 对应命令：# 查看Deploymentkubectl get deployments -n &lt;namespace&gt;# 查看Deployment详细信息kubectl describe deployment &lt;deployment-name&gt; -n &lt;namespace&gt;# 扩容Deploymentkubectl scale deployment &lt;deployment-name&gt; --replicas=5 -n &lt;namespace&gt;# 更新Deployment镜像kubectl set image deployment/&lt;deployment-name&gt; &lt;container-name&gt;=&lt;new-image&gt; -n &lt;namespace&gt;# 查看Deployment升级历史kubectl rollout history deployment &lt;deployment-name&gt; -n &lt;namespace&gt;# 回滚Deploymentkubectl rollout undo deployment &lt;deployment-name&gt; -n &lt;namespace&gt;# 暂停/恢复Deployment rolloutkubectl rollout pause deployment &lt;deployment-name&gt; -n &lt;namespace&gt;kubectl rollout resume deployment &lt;deployment-name&gt; -n &lt;namespace&gt;# 查看控制器管理的Podkubectl get pods -l &lt;label-key&gt;=&lt;label-value&gt; -n &lt;namespace&gt; 12.8 配置和存储资源 ConfigMap：存储非敏感配置数据 Secret：存储敏感数据如密码、密钥 PersistentVolume/PersistentVolumeClaim：提供持久化存储 对应命令：# ConfigMap命令# 查看ConfigMapkubectl get configmaps -n &lt;namespace&gt;# 查看ConfigMap详细信息kubectl describe configmap &lt;configmap-name&gt; -n &lt;namespace&gt;# 创建ConfigMapkubectl create configmap &lt;configmap-name&gt; --from-literal=key1=value1 --from-literal=key2=value2 -n &lt;namespace&gt;# 从文件创建ConfigMapkubectl create configmap &lt;configmap-name&gt; --from-file=config.properties -n &lt;namespace&gt;# Secret命令# 查看Secretkubectl get secrets -n &lt;namespace&gt;# 查看Secret详细信息kubectl describe secret &lt;secret-name&gt; -n &lt;namespace&gt;# 创建Secretkubectl create secret generic &lt;secret-name&gt; --from-literal=key1=value1 -n &lt;namespace&gt;# 从文件创建Secretkubectl create secret generic &lt;secret-name&gt; --from-file=ssh-privatekey=/path/to/key -n &lt;namespace&gt;# 查看Secret内容（编码后的）kubectl get secret &lt;secret-name&gt; -n &lt;namespace&gt; -o yaml# PersistentVolume/PersistentVolumeClaim命令# 查看PersistentVolumekubectl get pv# 查看PersistentVolumeClaimkubectl get pvc -n &lt;namespace&gt;# 查看PersistentVolume详细信息kubectl describe pv &lt;pv-name&gt;# 查看PersistentVolumeClaim详细信息kubectl describe pvc &lt;pvc-name&gt; -n &lt;namespace&gt; 13. 常见问题排查 在运维Kubernetes集群和应用时，掌握常见问题排查方法非常重要。以下是几个关键的排查入口和技巧： 13.1 从集群状态开始排查 首先检查集群整体状态： # 检查节点状态kubectl get nodes# 确保所有节点处于Ready状态# 检查核心组件状态kubectl get cs # (已弃用，使用下面的命令)kubectl get componentstatuses# 查看所有命名空间kubectl get namespaces# 检查命名空间中的资源kubectl get all --all-namespaces 12.2 检查Pod状态和事件 Pod是最基本的部署单元，是排查问题的起点： # 查看Pod状态kubectl get pods -n &lt;namespace&gt;# 查看Pod详细信息和事件kubectl describe pod &lt;pod-name&gt; -n &lt;namespace&gt;# 关注Events部分，通常包含错误信息# 检查Pod的YAML定义kubectl get pod &lt;pod-name&gt; -n &lt;namespace&gt; -o yaml 12.3 查看应用日志 查看应用容器的日志是排查问题的重要手段： # 查看Pod中主容器的日志kubectl logs &lt;pod-name&gt; -n &lt;namespace&gt;# 查看Pod中指定容器的日志（多容器Pod）kubectl logs &lt;pod-name&gt; -c &lt;container-name&gt; -n &lt;namespace&gt;# 查看最近的日志（例如最后100行）kubectl logs &lt;pod-name&gt; --tail=100 -n &lt;namespace&gt;# 实时查看日志流kubectl logs -f &lt;pod-name&gt; -n &lt;namespace&gt;# 查看过去一小时的日志kubectl logs &lt;pod-name&gt; --since=1h -n &lt;namespace&gt;# 查看重启前的容器日志kubectl logs &lt;pod-name&gt; --previous -n &lt;namespace&gt; 12.4 进入容器调试 当需要直接进入容器内部进行调试时： # 进入容器执行交互式命令kubectl exec -it &lt;pod-name&gt; -n &lt;namespace&gt; -- bash# 在容器中执行单个命令kubectl exec &lt;pod-name&gt; -n &lt;namespace&gt; -- ls -la /# 进入多容器Pod中的指定容器kubectl exec -it &lt;pod-name&gt; -c &lt;container-name&gt; -n &lt;namespace&gt; -- sh 12.5 检查资源使用情况 查看Pod和节点的资源使用情况： # 查看Pod的资源使用情况kubectl top pods -n &lt;namespace&gt;# 查看节点的资源使用情况kubectl top nodes# 获取Pod的详细资源配额kubectl describe pod &lt;pod-name&gt; -n &lt;namespace&gt;# 在"Conditions"和"QoS"部分查看资源相关信息 12.6 检查服务和网络 排查服务访问和网络连接问题： # 查看服务状态kubectl get svc -n &lt;namespace&gt;# 查看服务详细信息kubectl describe svc &lt;service-name&gt; -n &lt;namespace&gt;# 测试服务连通性（在集群内部）kubectl run test-pod --image=busybox --rm -it --restart=Never -- nslookup &lt;service-name&gt;.&lt;namespace&gt;.svc.cluster.local# 端口转发进行本地测试kubectl port-forward &lt;pod-name&gt; 8080:80 -n &lt;namespace&gt; 12.7 检查配置和密钥 验证配置和密钥是否正确挂载到Pod中： # 查看ConfigMap内容kubectl get configmap &lt;configmap-name&gt; -n &lt;namespace&gt; -o yaml# 查看Secret内容（注意敏感信息）kubectl get secret &lt;secret-name&gt; -n &lt;namespace&gt; -o yaml# 在Pod中检查挂载的配置kubectl exec -it &lt;pod-name&gt; -n &lt;namespace&gt; -- ls /etc/config 12.8 排查常见问题 Pod处于Pending状态 检查是否有足够的资源 检查节点选择器和污点容忍度配置 Pod处于CrashLoopBackOff状态 查看容器日志 检查启动脚本和配置 检查资源限制是否过小 Pod处于ImagePullBackOff状态 检查镜像名称和标签是否正确 检查镜像仓库访问权限 服务无法访问 检查Service和Pod的标签选择器是否匹配 检查端口配置是否正确 验证网络策略是否有误 12.9 使用Sealos排查集群问题 # 检查Sealos集群状态sealos status# 在节点上执行命令sealos exec --hosts 192.168.1.100 "systemctl status kubelet"# 查看集群证书信息sealos cert# 检查节点是否正常kubectl get nodes -o wide 13. 最佳实践 安全：始终使用RBAC控制访问权限，定期更新证书和密钥 监控：部署Prometheus和Grafana等监控工具 日志：使用EFK（Elasticsearch, Fluentd, Kibana）收集和分析日志 备份：定期备份重要数据和配置 网络策略：配置网络策略以限制Pod间通信 资源管理：使用ResourceQuota和LimitRange控制资源使用 通过遵循这些最佳实践，可以构建一个安全、可靠、高效且易于维护的Kubernetes集群。
